# 메리츠 속쓸 적립봇 (meritz_laoer · 서비스 meritz_laoer.service) — v2.0.5

메리츠 3번 계좌(Super365)에서 **SOXL 분할매수·부분매도**를 하는 봇. 기존 무한매수(V14) 봇 `meritz_laoer`를 고쳐 만들었다
(계좌 키 지문·텔레그램·장부·정지 장치·텔레그램 메뉴 재사용). 버전 번호·표시 이름은 Muse 가 정한다. `strategy_v14.py` 는 이제 안 불리지만 지우지 않았다.

## 규칙 (노션 작업 페이지 2026-11-18)
- 매수 사다리: **$50 부터 $5 내려갈 때마다 1회차**, 매수가 $50·45·…·5 (10회). 회차 금액 = 총 투자금(원) ÷ 10 ÷ 메리츠 적용환율(매수), 정수 주 내림.
- 매도: 평단 대비 **+10%** 에 보유 **50%** (정수 주 내림, 0주면 안 팖). 부분 매도라 평단은 그대로.
- 매도 뒤 = **재매수 모드**: 매도 시점 평단 − $5 × n 에서 1/10 씩 다시 매수 (기존 $50~$5 사다리는 안 씀).
- 한도: 보유 원가(달러) ≤ 총 투자금 ÷ 적용환율. 기존 보유분도 포함. 계좌 USD 예수금이 모자라면 **현금으로 살 수 있는 만큼만 부분 매수**(v2.0.4, 아래). 한도가 모자란 경우는 그 회차 생략.
- **1회차 차감**: 기존 보유(토스에서 옮겨 온 SOXL 등)의 원가를 **첫 사다리 매수 한 번만** 회차 금액에서 뺀다 (`start.first_round_credit_usd` 또는 `--add-shares … --credit`). 체결되면 소멸.
- **필요 달러**: 오늘 매수 주문이 다 체결될 때 드는 달러(= 주문 수량×가격 합계). 예수금과 비교한 **부족 달러**와 함께 계획·`--check`·텔레그램 💰 자금에 표시.
- **자동환전** (`auto_fx_enabled`, 기본 꺼짐): 켜면 부족 달러 + `auto_fx_buffer_pct`% (올림, 정수 달러)를 `auto_fx_max_usd_per_day` 안에서 원→달러 환전 신청한 뒤, **환전 후 실제 예수금**으로 계획을 다시 짜서 주문한다(모자라면 매수가 줄거나 빠짐).
  실주문 모드에서만·하루 한 번(신청 전 `data/fx_<날짜>.json` 기록, 실패·불확실해도 그날 재신청 안 함)·원화 예수금이 모자라면 안 함. 모의(dry_run)·`--check`·메뉴는 계산만, 환전 신청 없음. 환전 API 호출 형식은 meritz_dca_bot 과 같고 서버 수용 여부는 **실환전 전까지 미확인**(실환전으로 시험하지 않음).
- 매일 미 동부 `order_time_et`~`order_deadline_et` 사이 한 번: 다음 사다리 레벨 매수 주문(최대 `max_rounds_per_day`개) + 평단 +10% 매도 주문을 같은 방식(LOC 또는 LIMIT)으로 낸다. 체결은 `sync_time_et` 뒤 주문번호로 읽어 장부(`data/position.json`)와 적립 상태(`data/accum_state.json`)에 반영.

설정 예시 (**가상 값 — 실제 값은 Muse 가 채우고 GitHub 에 올리지 않음**, `.json` 파일로 저장소에 두지 않음):
```

"first_buy_mode": "<now|wait_top>", "unit_base": "<total|cash>", "max_rounds_per_day": <정수>,
"order_type": "<LOC|LIMIT>", "allow_consecutive_sell": <true|false>,
"start": {"qty": <정수>, "principal_usd": <원금>, "mode": "ladder", "filled_levels": [], "first_round_credit_usd": <1회차 차감액 또는 null>}
```
그대로인 안전 조건: enabled·dry_run·transfer_confirmed·toss_sniper_stopped_confirmed·키 지문·P/VR6 키·다른 봇 토큰 금지·장부=잔고·정지 표시·하루 1회 표시 파일.

## 명령
`--fingerprint` · `--check`(주문 없이 점검·오늘 계획) · `--inject-start`(장부+적립 상태 시작) · `--clear-halt` ·
`--add-shares --qty N --avg X [--credit]`(직접 산·입고된 N주를 평단 X 로 장부에 더함. `--credit` = 원가 N×X 를 1회차 때 차감. enabled=false·주문 시간 밖·잔고 = 장부+N 일 때만) · 인자 없음 = 상시 실행.
텔레그램 ➕ 직접 산 주식 반영: `63 61.50 차감` 처럼 끝에 '차감'.

## 현금 부분 매수 (v2.0.4, 사용자 결정 2026-11-19 Q15)
- 달러 예수금이 한 회차에 모자라면(총 투자금 한도가 아니라 **현금**이 모자랄 때) 회차를 통째로 건너뛰지 않고 **현금으로 살 수 있는 만큼만**(정수 주 내림) 산다. 1주도 못 사면 안 산다.
- 부분 매수한 회차는 체결되면 '채운 회차'로 친다 — 남은 주수는 이월·재시도 없음(예전 "남은 돈 이월 없음"과 같은 원칙). 다음 날은 다음 레벨.
- 총 투자금 한도가 모자란 경우는 예전대로 그 회차 생략. 자동환전이 켜져 있고 환전이 안 돼도(실패·상한) 환전 뒤 실제 예수금만큼 부분 매수.
- 계획 메시지·`--check`·📋 오늘 계획에는 "현금 부족 — $50.00 회차 299주 중 200주만 부분 매수" 문구와 주문 줄(`· 현금만큼 부분 매수 (원래 299주)`), 💰 자금에는 "현금 부족 → … 회차 N주만 부분 매수 (원래 M주)" 가 나온다.

## 주문 응답 유실 자동처리 (v2.0.4, Q19-3)
- 주문 **전에** '시도'를 그날 기록 파일(`data/orders_<날짜>.json`)의 `attempts` 에 먼저 저장한다. 하루 기록 파일은 첫 주문 전에 이미 있으므로, 도중에 응답이 끊기거나 프로세스가 죽어도 **같은 날 다시 주문하지 않는다**.
- 응답을 못 받으면(시간 초과·연결 끊김·응답에 주문번호 없음) **멈추지 않고** 그 주문을 `attempts` 에 남긴다. 서버가 오류 코드로 분명히 거절하거나 착오 방지 경고를 준 주문은 '안 들어감'으로 보고 `attempts` 에서 뺀다(알림에 실패로 표시).
- 자동 확인: 주문 직후 3번(5초 간격), 마감 뒤 체결 반영(`run_sync`) 때 한 번 더 — 체결 내역에서 **방향이 같고, 어느 기록에도 없는 주문번호이며, 체결 평균가가 주문가 범위 안**(매수 ≤ 주문가, 매도 ≥ 주문가)인 후보가 **딱 1건**일 때만 주문번호를 이어 붙인다(주문 직후엔 체결수량=주문수량, 마감 뒤엔 주문수량 이하). 0건·2건 이상이면 추측하지 않는다.
- 못 찾은 주문은 '체결 안 된 것'으로 두고(알림에 표시), 마지막 **잔고=장부 확인**이 안전망: 실제로는 체결됐는데 못 찾았다면 잔고≠장부로 예전처럼 정지한다. 이 봇이 낸 주문이 체결 내역에서 심볼로 걸러지는지(심볼 필드 이름)는 미확인 — 응답에 심볼 필드가 있으면 거르고 없으면 거르지 않는다.
- 장중 당일 매도 주문도 같은 방식(`send_order`)이다.

## 텔레그램 방 번호(chat_id) 필수 (v2.0.4, Q19-4)
- 텔레그램 설정 파일에 방 번호(`chat_id`)가 비어 있거나 없거나 숫자가 아니면(`@이름` 형식 포함) `--check`·`--add-shares`·주문 전 확인이 "텔레그램 방 번호…" 문제로 막는다. 메뉴는 등록된 방 번호와 **숫자로 같은 방**의 메시지만 처리하므로 숫자만 허용한다(그룹은 `-100…` 처럼 음수 가능).
- 방 번호 문제만 있으면 그날 하루 기록은 안 쓰고 5분마다 다시 확인해서, 고치면 같은 날 주문이 나간다(알림은 방 번호가 없어 로그에만 남는다). 다른 문제도 같이 있으면 예전 동작(그날 건너뜀 기록).

## 켜는 순서 (Muse·사용자)
1. 서버 `/etc/meritz-laoer/settings.json` 에 위 값을 채운다 (권한 600). 7번 무매(V14)의 미체결·진행 사이클이 없는지 먼저 확인 (노션 Q8).
2. `python3 main.py --check` → 3. 입고 확인 뒤 `transfer_confirmed=true` → `--inject-start` → 4. `enabled=true`(dry_run=true) 모의 → 승인 뒤 `dry_run=false`.

## 당일 매도 (v2.0.3, v2.0.4 에서 응답 유실 처리만 바뀜)
- 규칙은 그대로: 평단 +10% 에 닿으면 보유의 50% 매도, 직전에 매도했으면 재매수 체결 전까지 연속 매도 금지. 매수는 하루 1회차, 장중 재매수 없음.
- 달라진 것: 오늘 산 주식이 체결돼서 평단 +10% 에 닿으면 **그날** 50% 를 매도한다.
- 방법: 증권사에 주문 취소 기능이 없어서, 오늘 매수가 있는 날은 아침에 매도를 미리 걸지 않는다(`매도는 장중에 확인`). 주문 시간 안에 설정한 간격(`intraday_sell_check_sec`, 기본 120초, 0=끔)마다 현재가·체결·잔고를 확인하고, 평단(오늘 체결 반영) +10% 에 닿으면 1번만 매도 주문. 시도 기록을 주문 전에 남겨서 응답이 불확실해도 두 번 안 낸다. 오늘 매도 주문이 이미 있으면(아침·장중 어느 쪽이든) 더 안 낸다.
- 오늘 매수가 없는 날은 예전처럼 아침에 매도를 걸어 둔다. 장부·상태 파일은 16:10 이후 동기화 때만 바뀐다(장중 확인은 파일을 안 바꿈).
- 지정가(LIMIT)·실거래에서만 동작. 모의·LOC 는 끔.

## 자동환전 입력 (v2.0.3)
여유%와 하루 상한은 사용자가 텔레그램에서 직접 입력한다(기본값 없음). 💱 자동환전 화면과 ⚙️ 설정 양쪽에 🧮 환전 여유% 변경 · 💵 환전 하루 상한 변경 버튼이 있다. 값을 넣기 전에 켜기를 누르면 "여유%와 하루 상한을 먼저 입력해 주세요" 만 보여 준다.

## 화면 표시 규칙 (v2.0.3)
- 시드 `2억` 은 상황판·자금 화면에만, 당일 시드는 `2,000만원`.
- 소수점은 속쓸 가격(현재가·평단·매도 목표·사다리 가격·재매수 하락폭)만. 달러 예수금·필요 달러·회차 금액·환율·부족액은 정수.
- 영어 변수 이름은 화면·알림·오류에 안 나온다(`notifier.to_korean` 이 보내기 직전에 한 번 더 정리). 봇 상태는 `봇 켜짐 · 실거래`.

## 텔레그램 메뉴 (v2.0.3)
맨밑 4개가 메인: **💰 자금 · 📋 전술 · 📈 현상태 · 🛠 기타**. 카테고리 안 `🔙 뒤로` = 메인(설정 안은 전술, 봇 켜기/끄기는 설정, 자동환전은 자금).
- 💰 자금: 💰 자금 현황 · 💱 자동환전(켜짐/꺼짐 표시 + 켜기·끄기 + 🧮 환전 여유% · 💵 환전 하루 상한 입력)
- 📋 전술: 📋 오늘 계획 · ⚙️ 설정(시드 · 회차 · 목표 이익률 · 매도 비중 · 사다리 시작가·간격 · 재매수 하락폭 · 하루 최대 회차 · 환전 여유% · 환전 하루 상한 · 봇 켜기/끄기)
- 📈 현상태: 📈 상황판 · 📒 거래 내역 · 🤖 봇 상태
- 🛠 기타: 🔍 점검 · ➕ 주식 넣기 · 🛑 매매 정지 · ⛔ 정지 해제 · 📥 장부 시작 · 🔑 키 확인
설정 변경은 **설정 파일 값만** 바꾼다(주문 없음): 새 값 입력 → `이전 → 새` 표시 → `✅ 변경 확인`(60초). 봇·자동환전 *끄기*는 바로, *켜기*는 확인. 바꾸기 전 원본은 `data/settings_before_change.json`, 변경 기록은 `data/settings_change_log.json`. 모의/실거래 전환은 메뉴에서 안 바꾼다.
