## 10. 업데이트 대상 신규 주문 일시중지·재개 — 작성·검증 완료, 배포 전

### 확정 동작

- 사용자 요청: 6. Update에서 **이번 업데이트 대상 봇만** 제어. 모든 운영 봇을 무조건 끄지 않는다. 여러 대상은 ‘이번 업데이트 대상 전체 중지 대기’ 버튼 또는 대상별 버튼으로 요청하고, ‘이번 대상 거래 재개’/대상별 재개 버튼으로 해제한다.
- 잔고는 예수금이 아니라 **관리 종목의 보유 수량**을 뜻한다. 보유가 있으면 30초 주기로 조회한다. 대기 중 기존 전략의 매수·매도는 계속되므로 자연 청산이 없으면 계속 기다릴 수 있다. 강제 매도·주문 자동 취소는 하지 않는다.
- 보유 수량0 및 미체결/예약 없음이 확인되면 신규 매수·매도·정정 요청을 차단하고 알림. 기존 취소/조회 기능 자체는 유지한다. 알림의 ‘업데이트 진행’을 다시 눌러야 배포한다. 중지 요청 자체는 업데이트 승인이 아니다.
- 업데이트 후에도 차단 유지, 사용자가 재개 버튼으로 해제. 재개는 기존 master/power/enabled/종목 설정을 켜거나 초기화하는 것이 아니라 업데이트용 차단만 해제한다. 실패·충돌·재시작 뒤에도 파일에 저장된 차단을 유지한다. `거래 상태` 또는 `/pause_status`로 대기·중지 상태와 재개 버튼을 다시 볼 수 있다.
- 기존 매매 시간 보호는 기본 유지. **실제 차단 부품 실행·관리 수량0·주문 없음 재확인에 성공한 대상만** 해당 업데이트에서 시간 보호를 넘길 수 있다. 조회 오류·누락·NaN·연속조회 미완료·미체결은 0으로 취급하지 않는다. 장기 보유 봇은 조건을 만족할 때까지 업데이트가 계속 보류된다.
- 일반 잔고 폴링은 주문 잠금을 잡지 않는다. 0 후보를 찾으면 대상의 공유 주문 잠금에 배타 잠금을 잡아 진행 중 API 전송 완료를 기다리고 보유/미체결을 재검사한 뒤 중지 파일을 원자 저장한다. 동시 신규 주문과 중지 전환 사이의 틈을 막는다. async 주문은 취소돼도 배경 요청이 끝날 때까지 잠금 유지.
- 폴링 목표는 30초 주기이며 API 응답 지연·잠금 경합이면 실제 확인은 늦어질 수 있다. 네트워크 오류 안내/중지 알림은 성공 후 기록해 반복을 줄이고, 오류 중에는 대기 유지. 정확히 한 번의 Telegram 전달은 보장하지 않는다.

- 실행 확인은 systemd MainPID, /proc의 시작시각/명령/작업폴더, 설치된 transport/gate/초기 잠금 시각을 대조한다. 시작 후 설치된 부품이나 실제 로드가 확인되지 않는 상태는 거절한다. Python main.py 이외의 래퍼 구조/다른 인증 방식이면 해당 상태만 추가 확인이 필요할 수 있다.

### 7.5 업데이트 비서 주말 차단 수정 — 실제 적용 확인

- 원래 `busy_reason('toss_dca.service')`는 한국 10:50~15:10 또는 뉴욕 11:20~16:00이면 요일 없이 차단.
- 수정: 한국 조건은 한국 현지 weekday<5, 미국 조건은 뉴욕 현지 weekday<5를 각각 추가. 보호 시간 범위는 유지.
- 한국 토요일 새벽이 뉴욕 금요일이면 미국 보호 조건을 유지함.
- updater의 ET는 `ZoneInfo('America/New_York')`, KST는 `ZoneInfo('Asia/Seoul')`로 확인. DST 자동 반영.
- 이 수정은 공휴일 달력 판정까지 추가한 것이 아님. 평일 공휴일에는 여전히 시간상 차단 가능.
- 파일 `bot_office/bot_updater.py`, ZIP `updater_weekend_fix.zip`.
- 주말/현지 요일/시작·종료 경계/DST 11가지 가짜 시각 검증 통과.
- 사용자가 main 기준 `updater-weekend-fix` 브랜치에 파일을 올림.
- 기존 3번 변경과 함께 올리면 기존 updater가 3번 보호 조건 때문에 다시 막을 수 있어 별도 브랜치로 선행 적용하도록 안내.
- 미기록 toss_api.py 보존 commit 뒤 다시 승인해 2026-10-24 12:37 “업데이트 완료 / 5번 사무실 비서 v1.0.13 / GitHub main 업로드 완료” 및 “업데이트 비서 새 버전 정상 작동 확인”까지 실제 확인.
