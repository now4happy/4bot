### 5.3 3번 토스 주식들 스마트적립 — 확인된 기준 코드

2026-10-24 제공된 GitHub main의 `main.py`, `t_ui.py`를 내려받아 확인했다. 이후 서버·main이 바뀔 수 있으므로 현재 파일과 충돌하면 최신 실제 코드를 우선한다.

종목별 설정:
- `currency`: KRW 여부로 한국/미국 분류.
- `enabled`: 종목별 자동매매 켜짐/중지.
- `base_amount`, `s_mode`, `s_day`, `s_target_days`, `last_exec_date`, `sold_stage`, `has_held`.
- 전체 전원: `is_master_active`.
- 초기 화면 기준 기본 매수금: 한국 100,000원, 미국 40달러. 종목별 변경 가능. 현재 실제 투자금이라고 단정하지 않는다.

사이클:
- `buy_1`: 1차 100일 분할매수.
- `pause`: 지정 N일 정지 대기. enabled이고 실행 조건을 통과하면 일차만 증가.
- `buy_2`: 지정 N일 2차 분할매수.
- `sell`: 지정 N일 분할매도.
- `decision`: 기간 종료 후 다음 단계 결정 대기. 자동주문 건너뜀.
- 기간 완료 후 N일 정지/N일 분할매도/N일 2차매수를 사용자가 선택한다.
- 시작 버튼은 enabled=True로 설정한다. 즉시 주문 명령이 아니다. 전체 전원·시간·사이클·잔고 조건을 계속 적용한다.
- 중지 버튼은 신규 자동주문 차단용. 이미 접수한 주문 취소나 보유주식 청산 기능이 아니다.

매수:
- 수익률이 +1% 이상이고 평단·보유수량이 있으면 기준금액의 1/2, 그 외 기준금액 1배.
- 한국 정수 수량: `max(1, int(buy_amt // cur_p))`; 현재가가 없을 때 1주로 처리하는 기존 코드가 있었다. 따라서 기준금액이 엄격한 최대 한도라고 보장하지 않는다. 이 부분은 이번 UI 변경에서 수정하지 않음.
- 미국 매수: `smart_us_buy()` → 기존 주석상 달러 금액 매수와 관련된 API 사용. 정확한 주문 체결 방식·시장가/지정가 속성은 API 구현 확인 필요.
- 미국 달러 부족 검사는 익절 판단 뒤 수행한다. 달러가 부족해도 보유주식 익절 매도는 가능하도록 의도됨.
- 달러가 필요액보다 부족하면 주문 대신 실패 사유 기록. 사용자 자금 보충을 기다린다.

익절:
- 기본 `tp1_pct=10`, `sr_pct=20` (설정 가능).
- 수익률 10% 이상 20% 미만이고 1차 미실행이면 당시 잔고의 20% 매도.
- 20% 이상 30% 미만이고 2차 미실행이면 당시 잔고의 20% 매도.
- 30% 이상은 해당 기준 코드에서 추가 익절 없음. 화면도 미정/매도 없음으로 안내.
- 손실권으로 내려갈 때마다 물타기 배수를 늘리는 별도 규칙은 이 기준 코드에서 확인되지 않음. 하락 중 정기 분할매수와 2번의 물타기 전략을 섞지 않는다.
- 손절 로직은 확인되지 않았다.
- 한국 익절 수량은 정수이며 1주 이상·보유수량 이내 계산, 미국은 소수 수량 반올림 계산.

분할매도:
- 남은 일수 `max(1, target_days - day)` 기준으로 잔고를 나눔.
- 한국은 정수 수량으로 최소 1주·보유수량 이내.
- 미국은 소액/마지막 날 전량, 그 외 소수 수량 분할하는 기존 코드.

중복 주문·상태 보존:
- 종목 `last_exec_date`가 해당 시장 현지 오늘이면 실행 건너뜀.
- 매수 주문 식별자 `b_{today_str}_{sym}`. 익절 `tp{stage}_{today_str}_{sym}`, 분할매도 `s_{today_str}_{sym}`.
- 같은 식별자 사용 의도가 있어도 API가 중복을 항상 차단한다는 보장은 별도 검증되지 않았다.
- 매수 요청이 비-`API HTTP` 예외로 끊기면 체결 가능성을 고려해 당일 재주문 금지로 기록하고 일차는 증가시키지 않음. 토스 앱 확인·필요 시 진행일 보정 안내.
- `save_merged()`는 최신 설정을 다시 읽고 매매 진행 키만 합쳐 저장한다. 텔레그램에서 도중 변경한 enabled/금액 등을 덮어쓰지 않으려는 코드.
- 주문 직전 `stock_trade_allowed()`로 전체·종목별 상태 재확인. 이미 전송된 주문 취소나 원자적 중지 보장은 아니다.
- `has_held`가 있고 잔고가 0으로 판단되면 종목을 설정에서 제거하는 기존 흐름이 있음.

거래 시각:
- 한국: 코드상 한국시간 평일 11:00~15:00 사이 재시도, 11:15 이후 미진행 알림 확인.
- 미국: 코드상 `EST_TZ`의 평일 11:30~15:50 사이 재시도, 11:45 이후 미진행 알림 확인.
- scheduler 반복 대기 50초. 전체 `last_retry_ts` 및 실패 알림에 의한 재시도 제어도 있음.
- 이번 최신 t_core.py에서 EST_TZ=ZoneInfo("America/New_York") 확인(DST 반영). 과거 두 파일만 보고 정의 미확인으로 남겼던 항목은 갱신한다.
- `check_holiday()`가 호출되지만 확인한 scheduler에서는 휴장 안내에 사용되며 거래 실행 자체를 막는 조건으로 연결되지 않았음. 공휴일 거래 차단이 완성됐다고 단정하지 않는다.

화면의 일차:
- 기존 목록/상세에서 s_day=0이고 보유가 있으면 `auto_detect_cycle_days()`로 추정하던 코드가 있었다.
- 함수는 주문 이력을 시도하고, 없으면 보유금액/기준금액으로 일차를 추정하는 기존 구현을 화면에서 확인.
- QLD 1주가 2/100일로 보였던 것은 실제 2거래일 매수의 증거가 아니다.
- 작성한 목록 개선에서는 목록 전체 종목의 개별 조회·일차 추정 저장을 제거했지만 상세 화면의 기존 추정은 유지했다. 수동 보정과 자동추정 관계는 별도 미해결 검토 사항이다.

## 재생 로그 (v4.3.5, 2026-10-28 · start.md 규칙)

- 부품 `replay_log.py`(4번과 같은 파일). 봇 폴더 `logs/events-날짜.jsonl`(일반, 14일) + `logs/audit-날짜.jsonl`(감사, 권한 600, 14일). 날짜는 UTC. 서버 저널에는 같은 내용 한 줄 요약.
- 일반 로그에는 종목·수량·가격·금액·잔고·채팅 식별자를 넣지 않는다. 종목/주문은 `sym_ref`·`chain`(이 서버의 비밀 소금으로 만든 참조값), 원값은 감사 로그에만(`audit_ref` 로 연결).
- correlation_id: 텔레그램 `tg-<update_id>`, 스케줄러 `sch-kr|us-<날짜>-<회차>`, 주문 체인 `ord-<참조>`(같은 날 같은 종목·같은 주문번호면 같은 체인), 시작/종료 `svc-start|stop`.
- 건너뜀 이유는 종목·이유별 하루 1번(done_today, awaiting_user_decision, usd_insufficient …), 폴링·스케줄러·토스 API 성공은 10분 요약, 같은 오류는 1시간에 전문 1번 + 횟수 요약.
- 체결 확인(fill)은 봇이 조회하지 않음 → `fill_check=not_available`. 토스 주문 응답의 주문 식별자 키는 미확정이라 흔한 키(orderId 등)를 찾고, 없으면 `broker_id_found=false`.
- 재생: 봇 폴더에서 `python3 replay_log.py --last 30` · `python3 replay_log.py <correlation_id>` · `python3 replay_log.py --scan`(금지 값 검사).
