### 4.2 통합 잔액

- `/잔액`, `잔액`, `/balances` 또는 office_briefing.py --balances. 계좌별 표시하며 서로 다른 지표를 임의 합산·환산·상계하지 않는다. 조회만 수행하고 거래봇 호출/환전/이체 없음.
- KIS 원화 dnca_tot_amt, 달러 output2에서 crcy_cd=USD 한 행의 frcr_dncl_amt_2. USD 행 중복/없음은 조회 불가. 기존 홈 .env APP_KEY/APP_SECRET/CANO/ACNT_PRDT_CD, 실행 환경 우선. /home/gieokkim/data/token_<계좌번호>.dat 토큰을 읽기만 하며 발급/갱신/삭제/재저장하지 않는다. BRIEF_KIS_ENV/BRIEF_KIS_TOKEN으로 경로 지정 가능. CANO 8자리. 실전 GET 국내 TTTC8434R/해외 CTRP6504R.
- 토스 cashBuyingPower KRW/USD. 국내 매수 예정이 없어도 KRW 조회. 2·3번 인증이 같거나 반환 계좌ID 같으면 중복 조회/표시 생략, 다르면 각각 표시. 누락 인증은 확인 필요.
- 빗썸 balance 사용가능 KRW만. 코인 평가액/잠긴 금액 제외. RP는 후속 요청.
- 0과 실패/누락/NaN 구분, 한 계좌 오류가 다른 결과를 지우지 않음. 인증정보/오류 원문 노출 금지.
- 브리핑은 HTML 일반 줄 유지, UTF16 3500단위 이하로 분할 전송. 긴 한 줄은 plain escape 분할. 과거 강제 잘라내기 제한은 해소됨.
- 스나이퍼 필요금의 옛 SOXS 장부와 현재 전략 일치 검증은 미완료이며 잔액 조회 성공과 구별한다.

## 9. 주말 브리핑 중지·주식 휴장 안내 수정안 (2026-10-25)

- 사용자 요청: 주말 정기 브리핑 안 함, 한국장/미국장 휴장 알림. 거래봇·빗썸·서버 관리 일정은 변경하지 않는다.
- 변경 파일 `bot_office/office_briefing.py` 하나, 최초 기준 main 7524dad. 최신 원격 c2bb1c2에서 주말·휴장 처리 코드와 후속 버전 기록까지 확인했다. 실제 다음 정기 메시지/서비스 상태는 별도 미확인. 이전 ZIP을 최신 파일에 덮어쓰지 않는다.
- KST 토·일은 정기 실행 진입에서 즉시 종료해 잔고/가격 API도 호출하지 않는다. 주말 휴장 메시지도 별도 전송하지 않는다. 수동 /잔액 및 --print는 유지한다.
- 평일 KIS 국내휴장일조회 GET /uapi/domestic-stock/v1/quotations/chk-holiday, CTCA0903R, BASS_DT/CTX_AREA_FK/CTX_AREA_NK, 일치 bass_dt 행의 opnd_yn만 사용. 기존 토큰 읽기 전용, 발급/갱신 없음. 일자별 조회 결과(실패 포함)를 캐시하여 하루 한 번만 호출한다. 실패는 정상 개장으로 추정하지 않고 확인 불가 알림.
- 미국은 NYSE 공식 https://www.nyse.com/trade/hours-calendars 의 2026~2028 전일휴장 표를 내장. KST 오늘 밤 시작할 미국 현지 같은 달력 날짜 기준. 아침 뉴욕 전날 일요일을 보고 월요일 밤을 휴장으로 오판하지 않는다. 조기폐장은 전일휴장으로 알리지 않는다. 2029 이후 달력 확인 불가, 연장 갱신 필요. 돌발 임시휴장은 내장표에 자동 반영되지 않는 한계가 있다.
- 평일 휴장 또는 조회불가이면 별도 짧은 일정 알림 하루1회(성공 후 기록, 실패시 오후 재시도). 한 시장만 휴장이면 해당 상태를 머리말에 넣고 일반 브리핑 계속. 양 시장 휴장이면 일반 브리핑 없이 일정 알림만 보낸다. 따라서 평일 일반 브리핑 머리말에는 같은 휴장 상태가 다시 보일 수 있지만 별도 일정 알림은 중복하지 않는다.
- 캐시/알림 기록 `/var/lib/bot-office/briefing-calendar/state.json`, 파일 잠금과 원자 저장. 수동 미리보기는 캐시/전송을 하지 않는다. 전송 도중 종료시 완전한 1회 전송 보장은 아니다.
- 기존 오전9시/오후16:30 timer를 코드에서 필터하므로 unit 수정 불필요. 정기 service가 실행할 때 로드하는 파일이라 비서/거래봇 별도 재시작 불필요. 기존 배포 updater의 사무실 재시작은 그 절차를 따른다.
- 검사: 신규10 시나리오(주말 즉시종료, 양시장/한시장휴장, 미국 월요일, 조기폐장, 조회불가, 달력범위, 하루캐시, KIS GET) 및 기존 잔액8 테스트 통과, 문법 및 git diff --check 통과. 가짜 API/임시상태만 사용, 실계좌 휴장조회/주문/텔레그램 전송은 로컬에서 실행하지 않았다.
- KIS 공식 구현 근거 https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/chk_holiday/chk_holiday.py (1일1회 권고, opnd_yn 사용).
- 적용: Python 파일을 staging의 bot_office에 업로드 → 6. Update 업데이트 확인 → 새 대상/파일 확인 후 사용자 승인. 다음 평일 정기 응답으로 실제 적용 확인. MD 업로드 시점은 사용자가 결정한다.

## 구성과 필요한 추가 문서

- 저장소 bot_office/ → 서버 /opt/bot-office. bot-office.service와 bot-office-secretary.service는 별도다. 프로그램 번호5와 Telegram ‘7. 비서’를 혼동하지 않는다.
- Telegram 명령 변경을 적용한 때에만 별도 비서 재시작이 필요할 수 있다. 브리핑은 service 실행 시 파일을 읽으므로 문서 수정만으로 재시작하지 않는다.
- Gemini 판독 비용/선불 추정은 08_gemini.md. 제품 가격/웹·갤럭시 비교/Gbuts는 09_prices.md. 이 기능들을 수정하지 않으면 읽지 않는다.
- 사무실/업데이트/매매봇의 모든 DB·공유정보 연결이 검증된 것은 아니다. 자금 알림과 매매 집행을 같은 기능으로 취급하지 않는다.
- 현재 사용자 보류: 지역별 Claude 결제 비교는 한국 귀국 후 재개. 휴대폰 지역 전환을 서버에서 자동 감지할 연결은 없다.
