# 팬딩 가격표 → 메리츠 예약주문 (fanding)

갱신: 2026-10-26 · 저장소 main 0088727 코드 읽기 기준 (메뉴 항목만 2026-10-29 갱신). 서버의 실제 설정값(/etc/bot-office/fanding.json)과 실동작은 확인하지 못했다.
필수 작업 원칙은 루트 START.md를 따른다. 실주문으로 테스트하지 않는다.

## 흐름과 코드 위치
- Windows PC `fanding_windows/fanding_fetch.py run`(작업 스케줄러가 run.bat 실행) → 서버 `/api/fanding/upload` → `bot_office/fanding_trade.py`(bot-office-fanding.service) → Gemini 2회 판독·안전점검 → 5번 팬딩 봇 [✅ 주문]/[❌] 버튼 → `bot_office/meritz_client.py`로 메리츠 예약주문(SOXL).
- 자동주문·시간 계산: `deadlines()`, `tick()`, `run_checks()`, `submit()`.

## 자동주문 규칙 (코드 기본값)
| 항목 | 기본값 | 의미 |
|---|---|---|
| auto_order | True | 버튼을 안 눌러도 자동주문 |
| cutoff_et | 08:30 ET | "예약 마감". 장마감이 아니라 미국 정규장 개장 1시간 전(KST 21:30, 11/1 이후 22:30) |
| alarm_before_min | 30 | 마감 30분 전은 알림만 보냄(주문 아님) |
| auto_before_min | 10 | 마감 10분 전에 자동 승인 후 바로 접수 |
| reserve_time | "2" | 접수한 예약이 체결되는 시점(미국 장마감 30분 전 30분 VWAP). 접수 시점과 별개 |
- 자동주문 조건: auto_order 켜짐 + 가격표 대기 중 + 안전점검 전부 통과. 미통과면 "자동주문 안 함"(skipped) 알림만 보내고 주문하지 않는다.
- 점검이 막는 경우: AI 2회 판독 불일치·확인 판독 실패, 종가 날짜 불일치, 메리츠 시세 대조 실패(0.3% 초과 또는 조회 실패), 매수가·매도가 범위 이탈, 수량 1~500 밖, 매수 총액이 max_buy_usd(기본 8000) 초과, 매도 수량이 매도가능 초과(잔고 조회 실패 포함), 거래소 번호 없음.
- 마감 시각이 지나면 대기 중인 가격표는 expired(이번 주문은 넘어감).
- 질문 표현 주의: "마감 30분 전"에 자동주문하는 코드는 없다. 30분 전은 알림, 10분 전이 자동주문이다.

## 인터넷이 불안정할 때
- 자동주문은 서버가 실행하므로 사용자 폰 연결은 필요 없다. 연결이 끊기면 알림을 못 볼 뿐 주문은 진행된다.
- 서버 외에 필요한 것: Windows PC가 켜져 있고 인터넷·팬딩 로그인이 유지되는 것(매일 오전 실행, stop_at 11:30까지 5분 간격 재시도), 메리츠·Gemini 응답.
- 코드상 공백 (읽기 기준, 시험 안 함):
  1. 가격표가 서버에 안 오면 주문이 생기지 않는다. 알림은 KST 11:00 기준 1회뿐이고, 수집기의 실패 알림도 PC 인터넷이 끊기면 못 보낸다.
  2. 접수 중 증권사 오류·일부 실패(partial)는 자동 재시도하지 않는다. `tick()`은 partial을 처리하지 않아 [🔁 실패한 것만 다시] 버튼을 눌러야 한다.
  3. 증권사 "주문 착오 방지" 경고는 버튼 확인이 필요해 자동으로 넘어가지 않는다.
  4. 점검 미통과 시 직접 주문해야 한다.
- 후보(요청·구현 없음): 마감 전까지 partial 자동 재시도, 가격표 미도착 알림 시각 조정.

## 달러 표시·환전 (정리: 2026-10-26)
- 저장소 main의 `fanding_trade.py`는 이미 1.7.1이며 알림에 보유 달러·환전 필요 달러(부족 추정)를 표시한다(`account_snapshot`, `usd_cash`). 이 문서의 이전 초안에 있던 1.6.3 달러 표시 파일은 올리지 않는다.
- 메리츠 공식 명세(github.com/meritz-securities/open-api openapi.json 2026-10-22)에 환전 API가 있다: `GET /forex/v1/rates/applied`(적용환율·우대 적용 여부 prft_aply_clcd·스프레드 spead), `POST /forex/v1/exchanges`(실시간 환전신청). 우대 시간표는 API에 없다.
- 환전 실행은 구현하지 않았다. 사용자가 "평일 09:00~15:30에 부족액만 환전, 기본 꺼짐, `/환전확인`으로 계산만 확인" 설계를 선택했으나 버튼 메뉴 작업으로 넘어가 보류 상태다. 00_rules.md의 "자동환전 안 함"과 충돌하므로 다시 요청 시 규칙 변경으로 명시한다.
