## 3. 반드시 답할 질문

### Q1. 5-1·5-2·5-3은 별개인가, 묶을 수 있는가?
**구조상 하나로 묶을 수 있다** (스크립트가 한 시뮬레이터 안에서 동시에 돌린다 — `Sim.act_at`, `Sim.close_day`). 근거: 셋은 발동 시점이 서로 다르다.
- 5-1: 개별 익절 체결 직후, 같은 가격에서 (`evaluate_multi_grid_sell_targets` 의 개별 매도 결과에 얹음)
- 5-2: 졸업 판정(`hit_wma_grad`) 순간에 전량 매도 대신 트레일 시작
- 5-3: 하루 마감 판정(봇의 `execute_1600_daily_closing_settlement_plugin` 과 같은 시점)

**어느 쪽이 유리한지(묶음 vs 분리)는 숫자로만 답할 수 있어 아직 미확인** — 서버 명령 ④ 결과 표가 나와야 함. 그때 "5-1+5-2+5-3 묶음" 행과 단독·두 개 조합 행을 비교해 제안한다.

### Q2. 묶을 때 우선순위와 공유 상태 (스크립트 구현)
같은 가격·같은 날 겹칠 때 순서:
1. **5-2 트레일 진행 중**이면 정지선 판정이 최우선. 진행 중에는 본·서브 개별 매도, 졸업, 모든 매수, 5-1을 멈춤.
2. 일반 매도(`evaluate_multi_grid_sell_targets`). 졸업이 걸리고 5-2 조건(래칫 ≥6, 정규장)이면 트레일 시작.
3. 개별 익절 직후 5-1 짝 매도(같은 가격).
4. 매수(0주 새 사이클 → 1층 공석 재장전 → 신저가 추매 → 서브).
5. 하루 마감: 5-2 기한(10거래일) 전량 매도 → 5-3 쿼터 정리(트레일 중이면 건너뜀) → 무매매일 갱신.

공유 상태(원장에 없는 새 필드, 시뮬레이터 안에서만):
- 사이클 시작일(`cycle_start`): 5-2의 k 계산과 5-3의 40거래일 판정이 함께 씀
- 트레일 바닥선·고점·시작일: 사이클 종료 시 초기화
- 상쇄 적립금: 사이클 종료 시 0으로(설정 `pair_fund_reset_on_cycle_end`)
- 쿼터 정리 횟수·마지막 날: 사이클 종료 시 초기화

묶을 때 생기는 간섭(구조상 확인된 것. 손익 크기는 결과 표로):
- 5-1과 5-3이 **같은 '비싼 층'을 정리 대상으로 삼는다** → 먼저 실행된 쪽이 다른 쪽 대상을 줄임
- 5-1이 고가층을 줄이면 졸업가가 내려가 **5-2가 더 일찍, 더 낮은 바닥선으로** 시작
- 5-2 진행 중엔 개별 매도가 멈춰 **5-1 재원이 쌓이지 않음**, 매수도 멈춤
- 5-1·5-3의 부분 매도도 봇 규칙상 "본 매도"라 **`anchor_price`가 체결가로 바뀌고**(sniper_exit_plugin 매도 정산 규칙) **무매매일이 0으로 리셋** → 다음 추매 기준가가 바뀌고 서브 그리드 시작이 늦어짐. 계획 문서에 정해지지 않은 부분이라 코드 규칙을 따름
- 잃을 수 있는 것: 5-2가 켜진 동안의 회전 수익(개별 매도·추매 중단), 상태 필드 4종 추가에 따른 구현 복잡도

### Q3. 묶을 수 없다면 이유
해당 없음(묶을 수 있음). 그래도 지시대로 **5-1·5-2·5-3을 각각 켜고 끌 수 있게** 했고 시작값도 모두 설정으로 뺐다(5장).
