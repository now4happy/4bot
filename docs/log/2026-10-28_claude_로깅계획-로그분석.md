- 진행: 계획 작성 + 로그 분석 (코드 변경 없음, 서버 적용 없음). 로그 = 사용자가 수집 명령으로 받은 botlogs_1028_0722.txt (비밀값 가림).
- 기준: main 최신본 (STATUS 2026-10-28 07:04 KST 기준 버전)

## 2. 무엇을 남기나 (3층)

1. **사용자 경험 (ux)** — 들어온 것: 텔레그램 명령·버튼(callback data)·웹 요청 경로 / 나간 것: 봇이 보낸 메시지 본문·버튼 목록·수정/삭제. 이 둘만 있으면 대화 화면을 순서대로 재생할 수 있다.
2. **내부 동작 (op)** — 예약 작업 시작/끝·걸린 시간, 외부 API 호출(증권사·빗썸·Gemini·딥시크·텔레그램) 결과 코드와 시간, 매매 판단의 입력→출력(가격·RSI·장부값 → 매수/보류 이유), 업데이트 비서 단계(검사·병합·재시작·건강검사·복구).
3. **보이는 결과 (outcome)** — 주문 접수/체결/거절, 알림 전송 성공/실패, 배포 성공/실패·버전, 브리핑 전송 여부.

## 3. 형식 — 모든 봇 공통 한 줄 JSON

```json
{"ts":"2026-10-28T00:05:12Z","kst":"10-28 09:05:12","bot":"toss_dca","ver":"4.3.4",
 "run":"a1b2","trace":"tg-88231","kind":"ux.in","name":"button","data":{"cb":"buy_now"},"ms":null,"ok":true}
```
- `run` = 프로세스 시작마다 새 값 (재시작 구분). `trace` = 한 사용자 행동·한 예약 작업에 붙는 묶음 번호 → 버튼 하나가 만든 API 호출·주문·답장을 한 줄로 이어 봄.
- `kind`: `ux.in` / `ux.out` / `op` / `api` / `decision` / `outcome` / `error`(트레이스백 포함).
- 저장: `/var/lib/bot-logs/<봇>/YYYY-MM-DD.jsonl` (14일, 봇당 최대 50MB) + 같은 내용 한 줄 요약을 stdout(journald).
- **쓰기 전에 가림**: 토큰·앱키·시크릿·Authorization·쿠키 → `<가림>`, 계좌번호 → 끝 2자리만. 금액·수량·가격은 분석에 필요하므로 남김.

## 4. 만들 것 (비슷한 작업끼리 묶음)

- **묶음 L1 (가장 효과 큼)**: 공통 모듈 `botlog.py` (각 봇 폴더에 같은 파일 복사, 의존성 없음) + 3·4번 봇에 텔레그램 in/out·주문 결과·예약 작업·`except: pass` 자리 오류 기록. 3·4번 버전 올림.
- **묶음 L2**: 5번 사무실(웹 요청 경로·응답코드), 7번 비서(브리핑·PC 감시·팬딩 판독/주문), 6번 업데이트 비서(단계별 시간·결과)에 같은 형식 적용. 사무실 버전 올림.
- **묶음 L3**: `log_replay.py` — 봇·시간 범위를 주면 "사용자가 본 화면 + 그 사이 내부 동작"을 시간순으로 출력. 6. Update 에 `로그 보내기` 버튼(24시간 수집·가림·파일 전송).
- 1·2번은 원작자 코드 유지 원칙 → 고치지 않고 기존 journald·`logs/bot_app.log` 를 수집만 한다.
