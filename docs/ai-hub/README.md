# AI 협업 허브 (ai-hub) — 읽는 법과 규칙

기준 계획: MUSE AI 협업 시스템 최종 구현 작업 계획 v1.2 + 2026-11-05 사용자 승인 3건(아래 '승인 기록').
방식: **수동 전달 허브**. Muse가 작업 카드·상태·기억을 관리하고, 사용자가 각 AI 앱에서 직접 실행한다.
추가 API 비용 0원 · 새 서버/DB/API 연결 없음 · 기존 봇·사무실·업데이터 코드 무변경.

## 1. 이 폴더(GitHub)에 두는 것과 두지 않는 것

이 저장소(now4happy/4bot)는 **공개 저장소**다.

| 두는 곳 | 무엇 |
|---|---|
| GitHub `docs/ai-hub/` | 규칙(README·TASK_ID)과 **빈 양식**(templates/)만. 실제 작업 내용 없음 |
| Muse 작업공간 `ai-hub/tasks/` | 실제 작업 카드·결과·검수·출처·TASK_INDEX (경로는 Muse가 보고한 실제 경로를 따른다) |
| 미니컴 | 작업 내용이 100MB를 넘을 때 (아래 4절) |

- GitHub에는 병원·인사·개인정보, 계좌·주문 내역, 비밀번호·API 키·쿠키·토큰, 이메일을 올리지 않는다.
- 저장소 맨 위가 아니라 `docs/ai-hub/`에 두는 이유: 4bot `.gitignore`가 화이트리스트 방식이라 `docs/` 아래 .md만 올라간다.
- 이 폴더에는 **.md 파일만** 둔다. 업데이트 비서는 봇 폴더 밖의 .md 아닌 파일(.json·.yaml·.gitkeep 등)이 하나라도 있으면 같이 올린 업데이트 전체를 거부한다.

## 2. 역할 (고정)

| AI | 맡는 일 | 하지 않는 일 |
|---|---|---|
| ChatGPT | 기획·설계·분석 | 운영 코드 확정, GitHub 쓰기 |
| Claude | 개발·코딩·테스트 | staging·main 업로드, 서버 적용·재시작 (Muse와 사용자가 함) |
| Gemini | 이미지 판독·**독립 검수** | 자기가 만든 결과를 자기가 검수 |
| DeepSeek | **검색·자료 조사 전용** | 코딩·수정·GitHub 변경·최종 승인. 결과에 코드가 있어도 채택하지 않는다 |
| Muse | 작업 카드·상태·기억·검수 정리, 전달 패키지 작성 | 내용 초안 작성, 사용자 승인 없는 확정 |
| 사용자 | 최종 승인, 각 앱 실행·계정 전환, 대화 정리 | — |

## 3. 대화 정리 정책 (2026-11-05 승인)

목표: **대화는 정리되고, 업무 기억은 Muse에 쌓인다.**

1. 작업 대화는 처음부터 **ChatGPT 임시 채팅 / Claude 시크릿(incognito) 채팅**으로 연다. 기록에 남지 않으므로 지울 대상이 생기지 않고, 공유 계정의 다른 사람 대화를 건드리지 않는다.
2. 대화 첫 줄에 task_id를 적는다. 일반 채팅으로 열 수밖에 없으면 대화 제목 맨 앞에 task_id를 붙인다 (`MUSE-20261105-001 · 제목`).
3. 끝낼 때 AI에게 HANDOFF 블록을 출력하게 하고, 사용자가 그 블록을 Muse에 붙여 넣는다 (양식은 7단계 SESSION_CLOSEOUT.md에서 만든다).
4. Muse가 저장 → 다시 읽기(read-back) → task_id 일치를 확인한 뒤에만 "창 닫아도 됨"을 알린다. 저장 실패 시 "닫지 마세요".
5. 일반 채팅으로 연 대화는 `chat_cleanup: pending_delete`로 기록하고, **계정 주인이 앱에서 직접** 지운다.

안전 조건: 다른 사람 대화 삭제 금지 · 계정 전체 대화 삭제 금지 · 저장 실패 시 삭제 금지 · 자동 로그인/비밀번호·쿠키·세션 저장/계정 순환/사용량 제한 우회 기능을 만들지 않는다.
공식 대화 읽기·삭제 API는 ChatGPT·Claude 모두 없다 (2026-11-05 확인). 공식 수단이 생기기 전까지 자동 삭제는 하지 않고 '삭제 대기'로 둔다.

## 4. 저장 용량 규칙 (2026-11-05 승인)

- 기준: Muse 작업공간 `ai-hub/tasks/`.
- **작업 1건의 폴더가 100MB를 넘거나, `tasks/` 전체 누적이 100MB를 넘으면** 넘는 작업(오래된 completed부터)을 미니컴으로 옮긴다.
- 옮긴 작업은 TASK 카드의 `storage`를 `minipc`로 바꾸고 옮긴 날짜를 적는다. 카드(TASK.md)와 handoff 요약은 서버에 남긴다.
- 확인 시점 서버 여유: 디스크 37% 사용 · 남은 13GB, 메모리 총 958MB (사무실 상황판 서버실, 2026-11-05 08:26 KST).
- 미니컴으로 옮기는 방법은 아직 정하지 않았다 (6단계에서 정함). 자동 이동은 그때까지 없다.

## 5. 읽는 순서 (새 AI·새 대화)

1. 4bot 작업이면 START.md → STATUS.md (기존 규칙이 우선).
2. 이 README → TASK_ID.md.
3. 사용자가 붙여 준 작업 카드(TASK.md) 또는 handoff 요약.
4. 필요한 양식 1개 (templates/).

## 6. 기존 체계와의 관계

- 4bot 작업은 기존 그대로: 작업 기록 = `docs/log/날짜_AI_작업.md` 새 파일, 다른 AI 지시서 = `docs/instructions/`, 현재 상태 = STATUS.md(업데이트 비서만 씀).
- ai-hub는 **task_id로 그것들을 묶는 색인**만 더한다. 4bot 작업 카드의 `links`에 docs/log·docs/instructions 경로를 적는다.
- 운영 반영은 기존 staging → 6. Update ✅ 승인 그대로. 승인 문안 확인 시 task_id와 commit SHA를 같이 본다.
- 테스트 브랜치를 올리면 6. Update 알림이 뜬다. **테스트용 알림에는 ✅를 누르지 않는다** (누르면 main에 합쳐진다).
